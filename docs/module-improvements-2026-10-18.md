# 新增模块改进与验证（2026-10-18）

本轮对照项目架构图检查已有实现，并直接修复了助手交互、找店列表和管理端库存预热中的明确缺陷。
代码修改位于 local-perks；独立 EchoMindJava 工程仅用于核对审批接口契约，没有改动其源码。

## 已完成的改进

| 模块 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 助手审批 | 第一次确认后，服务端若返回另一个待审批动作，页面只展示文字，没有第二次确认按钮 | 识别 `requires_approval` 和新的 `pending_token`，逐次生成确认卡；每张卡绑定原会话 |
| 助手并发 | 点击审批没有全局忙碌保护；新对话可能被上一轮 SSE 的回调覆盖 | 审批期间防重复提交、等待回执后才能新建对话；流式请求用会话代次隔离旧回调 |
| 助手输入 | 中文输入法确认候选词的 Enter 会发出尚未完成的消息 | 处理 composition 状态、`isComposing` 与兼容事件 229，普通 Enter 和 Shift+Enter 保持原行为 |
| 助手显示 | 独立的 `| 文本 |` 行不能组成表格时，Markdown 段落循环不前进，页面可能卡死 | 非表格管道行按普通段落渲染；继续转义正文 HTML |
| 助手 SSE | 只识别 LF 分隔符，CRLF 事件无法解析 | 同时支持 LF/CRLF，验证逐字节分片的中文与事件边界 |
| 助手反馈 | 审批网络错误直接显示失败，可能误导用户重复操作 | 提示结果尚未确认，先查看订单或相关业务状态；不自动重放写请求 |
| 找店列表 | 请求尚未结束时切换排序，新请求被 loading 拦住；旧响应可能填入新排序 | 重置请求递增代次，旧响应、错误和 finally 均不修改当前列表 |
| 找店列表 | 加载失败被当成“已经到底”，无法继续翻页 | 保留已有结果、页码和未结束状态，提供重试按钮，重试仍请求失败的那一页 |
| 底部导航 | “地图”入口点击无响应 | 改为“找店”，跳转已有商铺列表；更新所有引用的脚本版本，避免旧缓存继续生效 |
| 管理端预热 | 检查 Redis 占用后再 SET，中间可插入正常抢券；库存键丢失的分支绕过原保护 | Lua 原子检查占用集合、比较库存快照并写入；键丢失同样执行保护 |
| 管理端预热 | 仅检查部分订单状态，取消订单的终身购买资格可能在丢键后被忽略 | 任何历史订单都禁止通过预热重置库存；非法 DB 库存直接拒绝；不再把剩余库存猜作初始总库存 |

另外去掉了抽屉首次打开时的重复加载，以及没有预设问题的登录入口中的无效“问助手”按钮。
README 补充评论模块 V3 迁移、对账默认观测模式和回归测试运行方法。

`target/module-improvements/` 独立输出可执行 JAR；临时 POM 在构建后删除。没有停止现有服务或重启应用。

本轮没有运行会扫描、修复全库库存的历史集成测试，也没有连接真实模型执行下单或支付。
浏览器用例证明页面在指定响应下的行为；它不能代替 MySQL、RocketMQ、EchoMind 和模型一起运行的全链路验收。

## 运维行为变化

`force=true` 仅允许对无历史订单、无 Redis 购买占用且库存快照未变化的券预热。
有历史订单的活动，即使 Redis 库存丢失也会拒绝；应暂停活动、排空消息并按账本恢复库存及购买资格。
原有对账默认观测策略保留，不能把单值 CAS 当作在线恢复任意活动的保证。

EchoMind 的持久化运行回执、重启后审批恢复和取消传播仍属于独立服务的后续可靠性工作。
本轮的前端错误提示与防重复点击不能替代服务端持久化幂等。
