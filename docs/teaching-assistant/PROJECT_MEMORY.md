# 教学助手：项目长期记忆

更新日期：2026-10-20（Asia/Shanghai）

这份文件记录用户已经确认的项目方向、首版范围与设计约束。后续方案和实现应先读取本文件；新的用户决定优先，并同步更新这里。具体首版范围见 [MVP_SCOPE.md](MVP_SCOPE.md)。

## 长期目标与核心任务

用户确认：基于自主实现的 Harness，结合 Jev 和按需引入的心跳机制，建设一个完整、全面的教学助手。首先完成作业批改，再围绕真实教学工作逐步扩展。

以下任务是长期产品设计的核心参照，不代表当前已经启用后台自动化：

> “周五前完成这次作业的初评，把争议项集中给我；确认后整理班级共性问题，准备一份十分钟补练。学生提交订正后，再检查这些问题是否改善。”

助手应逐步支持这个任务中的跨天等待、老师复核、评分标准变更、局部重评、多批次执行、中断恢复、资料检索、讲评与补练、订正和跨周跟进。

用户希望项目能够体现后端工程、AI Agent 与大模型应用能力，自主贡献需要体现在可检查、可测试的执行机制上。

用户进一步确认长期需求包括：学生个人学习情况分析、班级整体分析、跨次作业与订正的历史跟踪，以及教学资料和经确认经验的长期记忆。首版仍聚焦文本简答题批改，数据模型需要为这些分析保留必要来源与版本。

## 已确认的首版

- 输入和题型：电子文本简答题（用户于 2026-10-20 明确选择）。
- 工作流程：老师确认题目与评分细则 → 导入电子文本答案 → 批量分项初评 → 集中复核 → 汇总与导出。
- 产出：每个评分点的候选等级、建议分数、对应答案证据、需复核项目、老师确认后的结果。
- 首版使用批改草稿与老师复核机制；结果发布方式后续按实际教学流程确定。
- 具体学科、年级、数据导入格式、代码仓库与部署方式尚未确认。

## Jev 的定位

- 首个应用位置是按照明确评分细则，对每个独立评分点进行语义评估。
- 可以采用 Score 等结构化判断接口，保留候选等级分布和模型相关元数据。
- 评分等级到学生分数的映射，由老师确认的评分规则与程序确定；不能直接把模型的连续 Score 当作最终成绩。
- 置信度是模型输出分布的统计量，不等于真实正确率。复核策略需要通过老师已评分的样本验证，并抽查高置信度结果。
- 客观比对、分数计算、文件是否存在、是否截止等确定事项，由程序规则处理。
- 评语、错因归纳、报告和补练草稿可使用生成式模型；这些内容需能回溯到实际答案与已确认结果。
- Jev 使用可替换接口，并保留普通模型结构化输出的对照实现；是否扩大使用范围由评测结果决定。

参考：[Score](https://docs.typesafe.ai/primitives/score)、[Confidence](https://docs.typesafe.ai/confidence)。

## 自主 Harness 的定位

- 自主掌控任务状态、模型调用循环、工具执行、上下文组装、执行预算、恢复、权限与验收的关键逻辑。
- 模型 API Client SDK 可以使用。Claude Agent SDK 可以在后续作为可选执行器或对照，不默认承担自主核心。
- HappyClaw 作为产品与架构参考，用户尚未确认将其重新选为主开发底座。
- learn-claude-code 与 EchoMind 是现有参考资产；复用内容需要标明来源和新增贡献。
- 首版采用清晰、可恢复的批改工作流。仅在任务确实需要时增加动态规划和专业子 Agent。
- 主数据库已确认为 PostgreSQL，统一保存教学业务事实、任务状态、历史记录和审计；后续按需启用 pgvector 扩展，提供资料与经验的相似检索。
- 当前不同时维护 MySQL 与 PostgreSQL 两套业务主数据库。Redis、任务队列、多 Worker 与具体运行框架仍按实际需求选型，尚未最终确认。

## 学习分析与历史数据

- 学生分析：按知识点、评分点、作业与时间查看表现、错误重复情况、订正过程与复核后的结果。
- 班级分析：查看成绩分布、分项得分分布、共性问题、提交与订正情况；统计必须能回溯到原始记录。
- 历史事实：保存答案版本、初评、老师复核、评分细则版本、知识点关联、观察时间和订正记录。
- 长期记忆：保存有来源和适用范围的教学偏好、资料、案例及经确认经验。检索索引可从权威原始记录重建。
- 精确查询与统计使用 SQL；相似资料或案例召回可使用 pgvector。生成式模型基于已计算的指标和证据撰写分析，不凭空生成数值。
- 分析输出注明时间范围、样本量、评分规则与结果确认状态。不同题目难度、规则版本和样本覆盖可能影响比较，不能把原始分数变化直接等同于学习进步。
- 班级成员关系和知识点映射变化需保留必要历史，避免当前配置悄悄改变过去的统计口径。

## 记忆、心跳与权限原则

- 学生提交、分数、复核、进度属于结构化业务记录，不包装为向量记忆。
- 题目、评分细则、参考答案和课程资料需要版本化、可追溯，并按老师、课程与作业隔离。
- 老师的格式与评语偏好可显式配置；对评分尺度的修改需要形成可审计的新版本。
- 学生历史表现可服务于后续补练与教学跟进；当前作业按当前答案与固定评分标准评估。
- 后续跨任务经验应有来源、适用范围、有效性检查与老师确认；不自动将一次复核修改推广到所有任务。
- 新提交、评分修改、订正等优先采用事件触发。心跳用于到期检查、遗漏补偿、异常恢复与等待事项跟进。
- 心跳先检查结构化状态；只有需要语义判断时才调用模型。
- 学生答案和检索材料作为待评数据处理，不能覆盖老师确认的评分规则或系统执行权限。

## 后续演进顺序

1. 可复核的电子文本简答题批改：规则版本、分项初评、证据、复核、导出、质量基线。
2. 可靠任务执行：批次与步骤持久化、重试、中断恢复、去重、运行追踪。
3. 一次作业的教学周期：缺交与待复核跟进、共性问题、讲评和补练、订正复核。
4. 跨次教学协助：学生与班级学习分析、知识点变化、历史订正跟踪、教学资料复用、经确认的经验、按需多 Agent 协作。
5. 根据教师真实需求扩展备课、教学资料整理和其他教学事务。

这些阶段是路线图，不表示已实现。每个阶段以教师工作量、结果质量与故障恢复的实测结果决定推进。

## 评测约定

- 使用老师已评分的样本，固定题目、评分细则、模型与提示版本。
- 调整样本与最终评测样本分离，避免将评测答案作为示例泄漏。
- 对比普通模型初评、Jev 分项初评、加入复核分流的方案。
- 观察分项与总分偏差、严重误判、被遗漏的错误、老师复核耗时、成本、延迟。
- 工程验证覆盖批次中断、重复提交、评分标准更新、重复事件和局部重评。
- 所有指标以实际测量为准，不填入未经验证的性能或准确率结论。
