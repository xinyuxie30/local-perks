# 首版范围：电子文本简答题批改

状态：首版题型与 PostgreSQL 主数据库已确认，具体学科与工程仓库待定。

长期方向与决定以 [PROJECT_MEMORY.md](PROJECT_MEMORY.md) 为准。

## 用户与任务

老师希望将一份电子文本简答作业交给系统初评，集中查看需要判断的项目，修改并确认结果，得到可导出的批改记录。

## 最小工作流程

1. 建立作业：录入题干、参考材料、满分和分项评分规则。
2. 确认评分细则：模型可以起草，老师确认后生成固定版本。
3. 导入答案：先支持电子文本录入与批量导入的接口设计；首个文件格式待样本确认。
4. 建立批次：关联提交版本、题目版本、评分细则版本和模型配置。
5. 分项初评：按评分点分别调用可替换评估器，Jev 为首个候选实现。
6. 保存证据：关联原答案中的片段；引用片段必须能在保存的答案版本中找到。证据缺失或不支持结论时标记复核，不补造证据。
7. 计算建议分数：依据老师确认的等级到分数映射，保存计算过程。
8. 生成复核列表：综合分布不确定性、证据问题、输入缺失及抽查策略，优先展示需老师判断的项目。
9. 老师复核：修改结果、说明原因并确认。保留原始初评，不能覆盖审计记录。
10. 汇总导出：输出老师确认后的成绩、分项结果与反馈草稿，并区分待复核记录。

## 核心数据对象

- Assignment / Question：作业、题目与题目版本。
- RubricVersion / RubricCriterion：已确认的评分细则版本与独立评分点。
- SubmissionVersion：答案内容、提交者标识、题目与提交版本。
- GradingBatch / GradingItem / Attempt：批次、待评项目与每次执行记录。
- CriterionAssessment：候选等级、分布、置信度、证据、模型配置、建议分数与异常标记。
- TeacherReview：老师确认或修改的结果、原因、操作者与时间。
- Artifact / Export：汇总、导出文件和可追溯来源。

为后续学生与班级学习分析预留课程、班级、学生、成员关系、知识点及其历史关联。具体录入方式和首版界面范围后续确定。

上述名称用于说明领域对象，尚未锁定具体表结构或编程语言。

主数据库采用 PostgreSQL。首版关系数据直接使用普通表、约束与事务；需要资料或经验的相似检索时再启用 pgvector。向量不替代成绩、复核和任务状态的结构化记录。

## 执行与一致性要求

- 同一答案版本、评分细则版本和评估配置构成可识别的评估对象；重试增加 attempt，不制造无法区分的重复结果。
- 批次状态与每份答案的执行状态分开保存。
- 成功项目可复用，失败项目可单独重试；服务重启后能识别未完成工作。
- 每次评分标准更新产生新版本；重评明确选择受影响的对象并保留旧结果。
- 提交者在批改期间修改答案时形成新版本，不能悄悄替换正在评分的输入。
- 模型完成输出不直接等于批改完成：仍需检查字段完整性、等级范围、证据引用和分数计算。
- 输出格式校验通过不代表评分正确；正确性由独立评测和老师复核检验。
- 保留评分细则、提交、初评和老师确认版本，为后续按学生、班级、知识点和时间统计提供可追溯事实。

## 首版验收场景

1. 老师能够创建并确认一份分项评分细则。
2. 能导入一批电子文本答案并得到逐评分点初评。
3. 老师能同时看到原答案、评分细则、初评、证据和建议分数，完成修改与确认。
4. 一批答案处理中断后，能够继续处理未完成项目。
5. 重复提交同一批处理请求，不产生重复的有效评估结果。
6. 修改某个评分点后，可以按新版本重评受影响项目，保留原记录。
7. 能导出已确认结果，并清楚标明尚未复核的内容。
8. 能在固定样本上对比不同评估器，报告实际偏差、复核耗时和模型成本。

## 后续接口预留

- 新提交、细则更新、批次完成、复核完成事件。
- 可替换的模型评估器与工具执行器。
- 作业、课程资料与知识点的关联。
- 学生和班级统计查询、历史订正与知识点变化分析；区分初评与老师确认结果。
- 待办到期检查、事件补偿和订正任务恢复。

预留接口不意味着首版实现所有长期能力。纸质作业识别、复杂开放题、自动补练、多 Agent 与跨周教学记忆，按后续范围逐步建设。
