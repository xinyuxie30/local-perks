# 魔改第二批：限流 / 多级缓存 / 评论 / 管理端（2026-10-18）

> 本批次目标：在既有「秒杀 + MQ + 交易闭环」基础上补齐**高并发防护**、**缓存体系**、**社区互动**与**运维接口**，
> 同时把上一版遗留的并发/缓存缺陷修掉。所有改动均附边界用例，单测 + HTTP 双端验证。

## 一、新增能力

### 1. 注解式限流（AOP + Redis 滑动窗口）

- 注解：`@RateLimit(prefix, limit, windowSeconds, dimension, key, message)`
  - `dimension`：`IP` / `USER` / `GLOBAL`；`key` 支持 SpEL（如 `#voucherId`），优先级高于 dimension。
  - `USER` 维度在未登录时自动降级为 IP，避免匿名流量绕过。
- 算法：`rate_limit.lua`，ZSET 存 `时间戳`，先 `ZREMRANGEBYSCORE -inf (now-window)` 清窗口，再 `ZCARD` 判限，
  未超限 `ZADD` + `PEXPIRE(window+1s)`，返回剩余次数；超限返回 `-1`。
  - 时间取 `redis.call('TIME')`，多实例部署时不受本机时钟漂移影响。
  - 成员为 `毫秒时间戳:UUID`，避免同毫秒并发请求互相覆盖。
- 失败语义：`app.rate-limit.fail-open=true` 时 Redis 故障放行并告警；`false` 时转 fail-closed 直接拒绝。
- 响应：`X-RateLimit-Limit` / `X-RateLimit-Remaining` / 拒绝时 `429 + Retry-After`。
- 已挂载点：发码 5/60s/IP、登录 10/60s/IP、抢券 5/1s/用户、发笔记 1/5s/用户、发评论 3/5s/用户、上传 10/60s/用户。

### 2. Caffeine + Redis 多级缓存

```
请求 → 布隆过滤器（不存在直接拒绝）→ L1 Caffeine（纳秒级）
     → L2 Redis（queryWithPassThrough / 逻辑过期）
     → DB
```

- `ShopLocalCache`：`maximumSize` + `expireAfterWrite` + `recordStats()`，命中率可在管理端查看。
- `ShopBloomFilter`：Redisson `RBloomFilter`，启动时按 `tb_shop` 全量灌入；Redis 不可用时 fail-open（退化为只查缓存）。
- 失效链路：`update` 事务内 `updateById` → `afterCommit` 才删 L2 + 清 L1 + Pub/Sub 广播 `cache:invalidate:shop`，
  其他实例收到消息清自己的 L1，避免"先删缓存后提交事务"导致的脏读回填。
- 新增 `save(Shop)`：写库后补布隆，解决"新建店铺被布隆误判为不存在"。

### 3. 评论模块（两级评论 + 点赞 + 计数校正）

- 接口：
  - `POST /blog-comments`（限流 3/5s）
  - `GET /blog-comments/of/blog/{blogId}?current=1`（分页 + 每条主评论带前 3 条回复预览）
  - `DELETE /blog-comments/{id}`（软删除 `status=2`，主评论删除连带隐藏其回复）
  - `POST /blog-comments/{id}/like`（ZSET + Lua 原子 toggle）
- 校验：内容非空且 ≤255、笔记必须存在、只支持两级（三级直接拒绝）、不能跨笔记回复、`answerId` 必须与 `parentId` 同线程、一级评论不得带 `answerId`。
- 计数：`tb_blog.comments` 由 `refreshBlogCommentCount` **按可见评论重算**，不再 `+1/-1`，并发下不会漂移。
- `tb_blog_comments.status` 由 `Boolean` 改为 `Integer`（原映射会把 2 变成 true）。
- 索引：`idx_blog_parent(blog_id,parent_id,id)`、`idx_parent(parent_id,id)`、`idx_user(user_id,id)`（`db/V3__comment.sql`）。

## 三、边界用例（单测 18 项全绿）

`RateLimitAspectTest` / `MultiLevelCacheTest` / `CommentServiceTest` / `OrderStateMachineTest` /
`AdminGuardTest` / `SeckillConcurrencyTests` / `HmDianPingApplicationTests` / `RedissonTest` / `NormalTest`

覆盖要点：
- 限流：连打 N 次后第 N+1 次拒绝，窗口过期后恢复；响应头数值正确。
- 缓存：L1 命中时删掉 Redis key 仍能返回且不回填；`update` 后 L1 立即失效。
- 评论：三级拒绝、跨笔记拒绝、空内容/超长拒绝、越权删除拒绝、重复删除幂等、点赞切换计数、计数重算。
- 状态机：CAS 流转、重复投递不多扣、非法 payType、重复支付、已支付不能取消、重复核销、已核销不能退款、归属校验。
- 库存：取消回补、Redis key 缺失时关单只改 DB 不造 key、过期/未开始窗口拒绝。
- 并发：10 库存 / 100 并发下单不超卖。

## 五、已知取舍

- **退款不退库存**：`PAID → REFUNDED` 不回补库存、不移除 `seckill:order` 占位，属于"营销券终身一单"的防刷设计；
  未支付取消（`UNPAID → CANCELED`）才回补库存。两者语义不同，勿混用。
- **取消后不能立即再买**：占位与数据库唯一索引 `uk_user_voucher` 共同保证一人一单，取消后需走人工或后续"复活订单"方案。
- `spring.jackson` 默认输出 `LocalDateTime` 为 ISO 格式（`2026-10-18T00:26:37`），前端如需 `yyyy-MM-dd HH:mm:ss` 可加全局配置。
