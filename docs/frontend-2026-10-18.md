# 前端全站优化（2026-10-18）

承接后端第二批（限流 / 多级缓存 / 评论 / 管理端 / 缺陷修复），本轮把前端从"能跑"提升到"能用、经得起边界"，
并顺带修掉几个真实缺陷（含一个存储型 XSS、两处时间解析错误、一个 N+1）。

## 1. 公共层 `js/common.js`

| 能力 | 说明 |
| --- | --- |
| 超时 | 统一 8s（原 2s 对弱网和轮询太紧），单项接口可覆盖 |
| token | 每次请求从 `sessionStorage` 现取，避免"页面打开后重新登录仍带旧 token" |
| 错误文案 | `describeError()` 按 400/401/403/404/405/413/429/5xx 翻译；429 读 `Retry-After` 拼"请 N 秒后重试" |
| 401 | 记录 `redirectAfterLogin` 后跳登录，登录成功回原页 |
| 参数序列化 | `paramsSerializer` 对 key/value 编码并跳过空值（中文关键字/空参数） |
| `util` | `formatPrice`（分→元两位小数）、`formatScore`（37→3.7）、`formatDiscount`、`formatCountdown`、`formatTime`、**`toDate`**、`firstImage`、`imgFallback`、`debounce` |

## 2. 页面改动

- **首页 `index.html`**：搜索框接 `/shop/of/name`（260ms 防抖 + 下拉建议面板：封面/名称/商圈/人均）；无限滚动重写（提前 120px 触发、按 id 去重、`rows.length < 10` 判定到底、骨架屏、空态、到底提示）；点赞按后端 `data === true` 本地加减；布局改纵向 flex，分类 10 项不再挤压列表，底部导航贴底。
- **店铺详情 `shop-detail.html`**：删除写死的假评论，改真实探店笔记 `GET /blog/of/shop/{id}`；评分按 10 分制换算；券卡片新增状态机 `notBegin / ongoing / ended` + 按钮文案（未开始 / 已结束 / 已抢光 / 限时抢购 / 处理中）+ 每秒倒计时；`buying` 防重复提交；`visibilitychange` 校准计时器。
- **店铺列表 `shop-list.html`**：距离 / 人气 / 评分排序（`sortBy=comments|score` 走 DB，距离走 GEO）；分页去重 + 到底提示 + 骨架屏 + 空态。
- **订单页 `order.html`**：`/config/public` 下发 `orderHoldMinutes`，前端不再写死 30 分钟；未支付订单显示"请在 mm:ss 内完成支付"；到点 3s 后静默刷新等待后端关单；有未支付订单每 20s 静默刷新；顶部刷新按钮带旋转动画；空态引导去逛逛；布局改纵向 flex（原来 `calc(100% - 128px)` 在有提示条时会被底部导航盖住）。
- **个人中心 `info.html`**：笔记/评价/粉丝三个 tab 补空态与引导按钮；笔记项可点进详情；补上模板里引用但**从未定义**的 `toBlogDetail` / `onImgError`；`images.split()` 换成 `util.firstImage` 防 NPE；登出接口失败也清本地态并跳转。
- **笔记详情 `blog-detail.html`**：正文由 `v-html` 改为纯文本渲染 + `white-space: pre-wrap`（见缺陷 2）；图片区由 85% 屏高收到 `46vh`（最大 420px）+ `object-fit: cover`，正文和评论回到首屏；点赞改为本地增减 + 单独拉点赞列表，不再整页重查。
- **登录页 `login.html`**：验证码按钮先禁用再请求，成功才进入 60s 倒计时；手机号正则前置校验；未实现的"密码登录"改为提示。
- **全局样式 `css/main.css`**：`.foot` 补白底 + `z-index` + `min-height`（原来无背景色，列表滚动时图标"浮"在卡片上）。

## 3. 本轮修掉的真实缺陷

1. **时间解析错**（`order.html` / `shop-detail.html`）：后端返回 ISO `2026-10-18T01:18:20`，旧代码只把 `-` 换成 `/` 得到 `2026/10/18T01:18:20`，Safari/Chrome 均 `Invalid Date` → 订单页永远显示"支付已超时"、券卡片永远不显示"距结束"。新增 `util.toDate()` 统一处理（T→空格、-→/、去毫秒），`formatTime` 复用它。
2. **存储型 XSS**（`blog-detail.html`）：`v-html="blog.content"` 会把任意用户笔记正文当 HTML 执行，改为文本插值；编辑页仍按纯文本入库。
3. **底部导航透明**（`main.css`）：`.foot` 无背景色，滚动时卡片从图标间透出，观感像"图标飘在内容上"。
4. **个人中心死链**（`info.html`）：`toBlogDetail` / `onImgError` 未定义，点击"关注"tab 的笔记无反应。
5. **后端 N+1**（`BlogServiceImpl`）：`/blog/hot`、`/blog/of/shop/{id}`、`/blog/of/follow` 原来每条笔记各查一次用户 + 各问一次 Redis。改为 `fillBlogUsers()`（一次 `listByIds`）+ `fillBlogLiked()`（一次 pipeline 取所有 score，失败降级逐个查）。

## 5. 智能助手页面改版 `chat.html`

原版把所有东西塞进一条对话流：工具步骤、子 Agent 卡片、记忆列表、功能入口都在消息里，
既吵又难读。改版的原则是**对话区只放对话，其余全部收进侧栏与抽屉**。

| 区域 | 改法 |
| --- | --- |
| 左侧竖栏 68px | 品牌、新对话、返回首页、长期记忆、退出登录，图标改内联 SVG + hover 气泡；解决"进得来出不去" |
| 顶栏 | 标题 + 连接状态点；右侧 功能 / 专家 / 记忆 三个带图标的抽屉入口 + 新对话 |
| 执行过程 | 折叠块：默认单行「已完成 · 2 次工具调用 · 1 位专家 · 3 轮推理」，点开才展开工具步骤（名称 + 中文摘要 + 耗时）与子 Agent 卡片（角色 + 任务 + 摘要） |
| 记忆 | 全部移到右侧抽屉：默认只显示「＋ 新增一条记忆」，点开才出现表单（标题 / 内容 / 类型 / 取消 / 保存）；条目按类型着色（用户偏好蓝 / 反馈习惯绿 / 项目资料紫 / 参考资料灰） |
| Markdown | 自研渲染器覆盖标题、列表、表格、代码块、引用、分割线、行内加粗/代码/斜体/删除线/链接 |
| 交互 | 输入框自动增高、滚动跟随（nearBottom 判定）、回到底部按钮、停止生成、审批卡片（确认执行 / 取消） |
| 窄屏 | `max-width: 780px` 收起竖栏至 56px、隐藏功能/专家入口，只留记忆 + 新对话 |

验证方式：无头 Chrome 的 `--virtual-time-budget` 会把 SSE 的超时虚拟化，真实流式永远拍不到完整态。
因此用 `window.fetch` 垫片把固定事件序列（含 tool_start / subagent_start / approval）灌进**真实页面代码**，
逐帧截图验收；再用注入脚本做交互冒烟（抽屉切换、表单开关、过程展开、表格渲染）——
13 个动作全部 ok、`window.onerror` 无捕获。真实链路另跑一次 `/chat/agent` 回归：3 轮、2 个工具、结论正确。

## 7. 个人中心补齐与订单页校时（10-18 凌晨第二批）

### 7.1 资料编辑（`PUT /user/info`）
- 新增 `ProfileDTO` + `UserServiceImpl.updateProfile()`：昵称（非空、≤32 字）改 `tb_user` 并同步 Redis 登录态 hash；介绍/性别/城市/生日走 `tb_user_info` 局部更新，只覆盖显式传入的字段，避免"没传就清空"。
- 生日支持 `yyyy-MM-dd`，非法格式返回 400 语义的 `Result.fail`，不抛异常栈。
- 页面：`info-edit.html` 表单 + 保存后回写 sessionStorage；`info.html` 顶部简介为空时给引导入口。

### 7.2 我的评价（`GET /blog-comments/of/user`）
- 评价 tab 不再是"即将上线"占位：`queryMine` 分页返回当前用户的评论，联表带出笔记标题/封面/所属店铺（`MyCommentVO`）。
- 渲染为「店铺名 + 笔记标题 + 时间 / 内容 / 点赞数」，点击整行跳笔记详情；回复类评论带「回复」标记。
- SQL 只取 `status IS NULL OR status = 0` 的可见评论，被举报/删除的不出现。

### 7.3 粉丝 / 关注
- `GET /follow/counts/{id}`：关注数、粉丝数，标签页 `粉丝(n)/关注(n)` 实时显示。
- `GET /follow/fans/{id}`、`GET /follow/followees/{id}`：分页返回用户卡片（`listByIds` 批量取，按关系表倒序回填保证"最近关注在前"）。
- 粉丝 tab 渲染头像 + 昵称 + 回关/已关注按钮（`/follow/or/not/{id}` 并发补关注态，失败按未关注处理）；关注 tab 保留原"关注的人的笔记"Feed，标签数字改为真实关注数。

### 7.4 订单页时钟校准
- `/config/public` 原本就下发 `serverTime`，但前端没用。现在 `order.html` 用往返中点估算本机与服务端的时钟差，倒计时统一按校准后的"现在"计算，避免本机时钟偏快/偏慢导致"还剩 mm:ss"不准、甚至提前/延后触发关单轮询。

### 7.5 Nginx 配置（`conf/nginx.conf`）
- 传输优化：gzip（js/css/json/svg）、tcp_nopush/nodelay；`client_max_body_size 10m`（探店图上传 413 修复）；静态资源 `expires` 缓存；`/api`、`/cs-api` 反代保持不变。
